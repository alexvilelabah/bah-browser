name: download-chain
description: Get from a product/support page to the actual file on download sites.

---
Download sites usually go: list → package/file NAME link → that package's page → an accept/download button → the file starts (often via a "thank you" page).
1. A link named after a package ("Full Software Package", "Printer Driver", "macOS Installer") IS the next step — click it, though it is not the file itself.
2. On the package page, the button that starts the file is often worded as agreement: "Agree to the EULA and Download", "Accept and Download", "Download Now". The LIKELY DOWNLOAD BUTTON line gives its [id]; scroll or use find if it is below the fold.
3. Do NOT go back to the list or the site's "Downloads" menu from a package page — use back only if you picked the wrong package.
4. An official vendor download page in search results is the right next step even if it is a page, not a file.
5. Big files (OS images, ISOs, SDKs): prefer the project's release INDEX (a plain listing of versions and files) over marketing "Download" buttons, then use the download action with the direct file URL.
6. Ignore optional extras (newsletter, upsell, surveys). The file is done only at DOWNLOAD COMPLETED.
